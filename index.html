Motivación y objetivos

El problema

Los gimnasios pequeños gestionan las reservas con papel, WhatsApp o Excel. Sin control de aforo, sin historial, sin automatización.

La solución

Plataforma web completa desplegada en producción real con HTTPS, Google OAuth, sistema de reservas semanal, planes de suscripción y panel de administración.

Objetivos específicos

  • Sistema de reservas con control de aforo en tiempo real
  • Autenticación con email/contraseña y Google OAuth 2.0
  • Planes de suscripción (Free, Básico, Premium)
  • Panel de administración con CRUD completo
  • Validación de DNI español (algoritmo mod-23)
  • Despliegue en hosting compartido real con Nginx
  • Interfaz responsive con diseño propio dark-mode

Google OAuth 2.0 — Implementación

GoogleController — callback()

GoogleController.php
public function callback()
{
  set_time_limit(60); // evita timeout en hosting compartido

  try {
    // stateless: no usa sesión-cookie para el state
    $googleUser = Socialite::driver('google')
                    ->stateless()->user();
  } catch (\Throwable $e) {
    Log::error('Google OAuth error', [...]);
    return redirect()->route('login')
        ->with('error', 'No se pudo conectar con Google.');
  }

  $user = DB::table('gym_users')
    ->where('google_id', $googleUser->getId())
    ->orWhere('email', $googleUser->getEmail())
    ->first();

  if (!$user) {
    $userId = DB::table('gym_users')->insertGetId([
      'profile_completed' => 0, // obliga a completar perfil
      'google_id' => $googleUser->getId(), ...
    ]);
  }

  Auth::loginUsingId($user->id);

  if (!($user->profile_completed ?? 1))
    return redirect()->route('profile.complete.form');

  return redirect()->route('dashboard');
}

Provider personalizado — endpoint actualizado

App\Socialite\GoogleProvider.php
// El vendor del servidor usaba el endpoint
// deprecado /v4/token → Google devolvía
// invalid_grant. Solución: sobrescribir URL.

class GoogleProvider extends BaseGoogleProvider
{
  protected function getTokenUrl(): string
  {
    return 'https://oauth2.googleapis.com/token';
    // antes: googleapis.com/oauth2/v4/token
  }

  public function getAccessTokenResponse($code): array
  {
    $fields = $this->getTokenFields($code);
    $response = $this->getHttpClient()->post(
      $this->getTokenUrl(),
      ['form_params' => $fields]
    );
    return json_decode($response->getBody(), true);
  }
}

  El provider se registra en AppServiceProvider::boot() con Socialite::extend('google', ...) para que reemplace al driver por defecto.

Middleware personalizados y control de acceso

AdminMiddleware

AdminMiddleware.php
public function handle(Request $request, Closure $next)
{
  if (!Auth::check() ||
      Auth::user()->role !== 'admin') {
    abort(403, 'Acceso denegado.');
  }
  return $next($request);
}

RequireProfileComplete

RequireProfileComplete.php
public function handle(Request $request, Closure $next)
{
  if (Auth::check()) {
    $completed = Auth::user()->profile_completed ?? 1;
    if (!$completed && !$request->routeIs('profile.complete.*')) {
      return redirect()->route('profile.complete.form');
    }
  }
  return $next($request);
}

Validación DNI — algoritmo mod-23

GoogleController.php — dniRule()
private function dniRule(): \Closure
{
  return function ($attr, $val, $fail) {
    $val = strtoupper(trim($val));

    // Formato: 8 dígitos + letra
    if (!preg_match('/^[0-9]{8}[A-Z]$/', $val))
      return $fail('Formato inválido: 12345678Z');

    // Mod-23: tabla oficial del Ministerio
    $letters  = 'TRWAGMYFPDXBNJZSQVHLCKE';
    $num      = (int) substr($val, 0, 8);
    $expected = $letters[$num % 23];

    if (substr($val, 8, 1) !== $expected)
      $fail('La letra del DNI no es correcta.');
  };
}

Retos técnicos superados en producción

502 Bad Gateway en el callback de OAuth

Causa: SESSION_DRIVER=cookie — la URL del callback (?state=&code=&scope=...) tiene ~580 chars. Al guardarse encriptada como _previous.url supera el límite de 4096 bytes de la cookie. Nginx devuelve 502.

  Solución: cambiar a SESSION_DRIVER=file — la sesión se guarda en el servidor, la cookie solo contiene el ID.

invalid_grant al intercambiar el token de Google

Causa: el vendor del servidor tenía una versión antigua de Socialite que usaba el endpoint deprecado googleapis.com/oauth2/v4/token, rechazado por Google con 400 Bad Request.

  Solución: provider personalizado App\Socialite\GoogleProvider que sobrescribe getTokenUrl() apuntando a oauth2.googleapis.com/token.

Target class [admin] does not exist

Causa: el bootstrap/app.php del servidor era antiguo y no registraba los alias de middleware personalizados. Laravel intentaba resolver el string 'admin' como clase.

  Solución: actualizar bootstrap/app.php con $middleware->alias([...]).
